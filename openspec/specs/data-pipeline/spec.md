# data-pipeline Specification

## Purpose
The Python pipeline (`dataParser/`) that extracts game data into the datasets the app consumes: per-language items, stats, client strings, trade configuration and styles, emitted under `dataParser/output/` and shipped with the renderer for parsing and UI.

## Requirements

### Requirement: Generated datasets
The pipeline SHALL generate per-language outputs (`items.ndjson`, `stats.ndjson`, `client_strings.js`) from game data providers, keyed by language code, and the renderer SHALL load these files for item parsing and localization.

#### Scenario: App renders in Russian
- **WHEN** the app runs with the Russian language selected
- **THEN** parsing and UI use the `ru` datasets generated by the pipeline

### Requirement: Reproducible pipeline runs
Running `python ./src/main.py` SHALL regenerate the outputs from the configured providers deterministically, with provider and service configuration kept in `dataParser/data/`.

#### Scenario: Data refresh
- **WHEN** a new game patch arrives and the pipeline is run
- **THEN** the ndjson outputs and client strings are regenerated for all supported languages

### Requirement: Pipeline tests
The pipeline SHALL stay covered by pytest so model and provider changes are verified.

#### Scenario: Model change
- **WHEN** a data model is modified and pytest runs
- **THEN** the suite validates the change against the contracts
